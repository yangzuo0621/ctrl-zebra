# 阶段 17：界面一致性与内容呈现

## 1. 阶段目标

让聊天界面使用一致、可访问的产品语言，并安全呈现常见技术 Markdown，同时修复已确认的消息样式
和高价值视觉缺陷。

## 2. 前置条件与范围

- 阶段 16 已完成。
- T1701 在实现前把目标语言或本地化策略写入 `docs/ux.md` 与 `docs/webview.md`。
- T1702 在引入依赖前完成 Markdown、链接、CSP、流式和资源边界的 docs-only 约束。

本阶段不包含富文本编辑器、任意 HTML、远程图片、网页预览、语法高亮依赖、本地化平台或整体视觉
重设计。

## 3. 任务

### T1701：统一产品语言与字符串所有权

确定 Marketplace 目标语言或最小本地化策略；集中管理 Webview 用户可见字符串；统一屏幕阅读器
播报、状态和错误文案。测试可见文本、ARIA、动态状态和不再混用未批准语言。

### T1702：实现受限的技术 Markdown 呈现

在安全契约通过后选择维护良好、许可兼容且体积合理的解析方案。支持标题、列表、代码、强调、引用、
表格和链接；禁用原始 HTML；只允许批准的链接协议并由 Extension/VS Code 打开外链。

测试 XSS、危险协议、嵌套/畸形 Markdown、超长内容、流式未闭合结构、复制、键盘和取消后的稳定投影。

### T1703：修复消息样式与界面细节

修复 assistant role 选择器失配及同范围内已有证据的布局、主题和状态问题。不得借此重构整个组件树
或引入新的设计系统。先加最小回归测试，再修复行为。

## 4. 阶段门禁

- 用户可见语言策略一致，屏幕阅读器不会无意切换语言。
- Markdown 不能执行 HTML、脚本、命令、文件、未批准 URI 或远程内容。
- 普通文本、代码、长内容、四类 VS Code 主题、约 300px 和 200% 缩放路径通过。
- 新依赖的维护状态、许可、体积和运行时兼容性有记录。
