# 阶段 12：审批安全回归修复

## 1. 阶段目标

修复 [UX-002](../ux-findings.md#ux-002pr-126-嵌式审批卡隐去风险等级标识确定性安全回归) 记录的确定性安全回归，使内嵌文件修改与命令审批在用户决策时显式展示可信 Tool 定义提供的 `write` 或 `execute` 风险等级。

本阶段只恢复现有 [安全规范](../../security.md) 与 [用户体验规范](../../ux.md) 已要求的信息，不改变审批协议、风险判定、授权边界或 Tool 生命周期。

## 2. 前置条件与顺序

- 阶段 0–11 已完成，现有审批请求、Tool 卡嵌入模式和安全规范保持有效。
- 本阶段仅包含 T1201；完成并通过阶段门禁后归档阶段规格。
- 实现前先添加能够复现内嵌模式缺失风险标识的最小回归测试。
- 涉及 React 或 Testing Library 时，执行实现前通过 Context7 获取当前文档。

## 3. 任务规格

### T1201：恢复内嵌审批风险等级标识

**目标**：在 `ApprovalCard` 的内嵌模式中恢复显式风险等级标识，使文件修改审批显示 `write`、命令审批显示 `execute`，并确保状态和风险不只依赖颜色表达。

**产物**：

- 内嵌文件修改审批与命令审批均显示来自不可变 Approval Request 的风险等级。
- 风险标识与现有 `Awaiting Decision` 状态同时可见，不以状态文案替代风险。
- 回归测试覆盖内嵌模式的 `write` 与 `execute` 风险，并保留非内嵌模式的既有行为。

**测试**：

- 先添加最小失败回归测试，再实现修复。
- 运行 Webview 相关组件测试与类型检查。
- 人工验证文件修改和命令执行的待审批卡片，并覆盖 Light、Dark、High Contrast、High Contrast Light、约 300px 宽度、200% 缩放和纯键盘审批流程。
- 完成既有仓库级检查以及 `git diff --check`。

**排除项**：

- 改变 `read`、`write`、`execute` 或 `network` 的风险分配与审批策略。
- 修改 Approval Request、Protocol DTO、审批有效期、消费语义或不可变操作绑定。
- 恢复原始 Tool JSON 参数、重新设计 Tool 卡或审批卡、调整其他状态 Badge。
- 顺带处理 UX-001 的待验证设想或后续能力候选。

## 4. 阶段门禁

- 文件修改与命令执行的内嵌待审批卡片分别显式显示 `write` 与 `execute`。
- `Awaiting Decision` 状态与风险等级均可独立识别，风险不只通过颜色表达。
- 非内嵌审批呈现和批准、拒绝、查看 Diff、命令摘要等既有行为无回归。
- 实现不改变协议、安全语义、持久化格式、模块边界或产品能力范围。
- 自动化检查与规定的人工场景均有可报告的验证结果。
