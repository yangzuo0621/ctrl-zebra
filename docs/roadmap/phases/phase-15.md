# 阶段 15：多轮对话与上下文生命周期

## 1. 阶段目标

先建立生产重试、覆盖率和跨平台证据，再让用户在同一个本地 Session 中继续提问，并让后续回合
在明确、可恢复且有界的历史上运行。多轮能力不得削弱取消、审批、Tool 生命周期、持久化兼容、
错误可诊断性或资源上限。

最小用户路径：开始新会话 → 完成一轮模型与 Tool 循环 → 在同一会话继续提问 → 第二轮收到
包含必要历史的回答 → 新建会话时不继承旧历史 → 重启后恢复已完成会话并继续提问。

## 2. 前置条件与范围

- 阶段 0–14 已完成并合入 `main`。
- T1501–T1503 必须在 T1504 的多轮契约 PR 之前依次完成。
- T1504 的独立 docs-only 约束 PR 必须先合入，之后才能修改多轮 Protocol、Core、Extension 或
  Webview；约束 PR 与实现 PR 共享 T1504 状态。
- 一个 Session 承载多个顺序回合；本阶段不新增 Conversation 聚合实体。
- 历史只来自已验证的本地 Session 记录，重建结果仍是不可信模型上下文。
- 每个新回合获得新的 Run 身份；上一回合的审批、待执行操作和取消句柄不得复用。

本阶段不包含跨会话记忆、分支对话、编辑历史消息、重新生成、后台自动续跑、并行回合、
Plan/Act、Skills、多 Agent、并行 Tool Calls、放宽最大 Tool 步数、精确 vendor tokenizer 或
持久化摘要服务。

## 3. 任务

### T1501：接通生产 Model Gateway 重试

**目标**：让现有受控重试层进入生产 Gateway 选择路径，在任何输出发出前处理短暂限流和不可用。

**产物**：所有现有 Provider 使用同一 Core-owned 重试语义；AI SDK 内部重试继续禁用；延迟、次数、
可重试分类、首次事件门禁和取消行为保持唯一来源；不得重构无关 Provider 工厂。

**测试**：首次 429/503 后成功；不可重试错误；已发出事件；退避期间取消；第二次仍失败；
Gateway 选择器对三个 Provider 的回归。

**不包含**：Tool、MCP Server、用户请求或上下文溢出重试。

### T1502：建立覆盖率基线与防回退门禁

**目标**：在多轮状态机和 Runtime 主循环改造前记录真实测试保护水平并阻止无意下降。

**产物**：通过 Context7 核对当前 Vitest coverage 配置；测量各项目真实基线后设置略低于当前水位的
可解释阈值；CI 生成机器可读结果但不提交 coverage 产物；阈值只能通过独立证据调整。

**测试**：本地 coverage 命令成功；人为低于阈值时失败；node/jsdom 项目均计入预期范围；
生成文件被忽略且不进入 VSIX。

**不包含**：为了提高数字而补写无行为价值测试，或一次性追求任意百分比。

### T1503：建立跨平台 CI 基线

**目标**：在多轮和更多 VS Code 宿主功能进入实现前，证明 Windows、macOS 和 Linux 的基础检查路径。

**产物**：受控 OS matrix；固定版本的 Actions 与 pnpm/Node 工具链；平台特有失败保持可区分；
昂贵的 VSIX/Extension 测试只在有明确收益的矩阵位置运行；不降低现有 provenance 和安全门禁。

**测试**：三个 OS 的格式、类型和单元测试；Windows 路径/CRLF/进程测试的最小证据；
macOS 文件系统差异；失败 matrix 不被静默忽略。

### T1504：确定多轮 Session 的产品与跨边界契约

**目标**：在实现前确定回合边界、状态复位、历史重建、兼容、取消和用户控制语义。

**产物**：

- 独立 docs-only 约束 PR，更新 `docs/architecture.md`、`docs/protocol.md`、
  `docs/persistence.md`、`docs/security.md`、`docs/ux.md` 和 `docs/webview.md`。
- 明确 `completed`、`cancelled`、`failed`、`interrupted` 会话能否开始新回合，以及失败或中断回合
  的用户消息、助手内容和 Tool Call/Result 如何进入历史。
- 定义省略 Session 身份时创建新会话、提供 Session 身份时续接，以及显式 New chat 的严格消息契约。
- 定义 Run 身份、审批失效、历史有序投影、损坏记录处理、旧版本会话兼容和资源上限。
- 约束合入后实现 Protocol Schema、解析测试和兼容 fixture；约束 PR 不把任务标记为已完成。

**测试**：新建/续接/New chat Schema；未知或错配 Session；旧消息兼容；严格对象拒绝额外字段；
序列化边界和大小上限。

**不包含**：Core 状态机和生产会话执行。

### T1505：接入 Core 回合复位、历史注入与裁剪

**目标**：让 Agent Runtime 在新的 Run 中安全消费既有模型历史。

**产物**：合法的回合复位状态转换；历史通过注入接口进入 Runtime；上下文预算和历史裁剪进入
生产路径；Tool Call/Result 保持成对；取消后不再裁剪、调用模型、重试或产生事件。

**测试**：正常第二回合；空历史；超预算裁剪；最新用户消息保留；孤立 Tool 历史拒绝；
第二回合取消；非法状态转换；审批不可跨回合复用。

**不包含**：持久化事件到模型历史的 Host 投影。

### T1506：重建持久化历史并续接 Extension Run

**目标**：由 Extension 从已验证 Session 事件重建 Core 模型历史，并区分创建与续接。

**产物**：Host-owned 历史投影；完整 Tool Call/Result 配对；损坏、截断和未完成尾部的确定性处理；
续接时不重复创建 Session；新 Run 拥有独立取消与资源所有权。

**测试**：多轮文本；完整 Tool 对；孤立 Tool；空会话；损坏记录；旧版单轮会话；未知 Session；
取消和关闭竞态；不重复 `create()`。

**不包含**：Webview 会话选择行为。

### T1507：实现 Webview 会话延续与 New chat

**目标**：让用户清楚知道当前会话，并能续接或显式开始新会话。

**产物**：复用 T1506 已接通的 `webview/submit.sessionId → WebviewRunMessageHandler → ChatRunner`
续接路径；Webview 只保存 Host 在 Run 启动或会话恢复时确认的 Session 身份，首次提交省略该身份，
同一会话的后续提交携带该身份；New chat 清空当前投影和陈旧附件；恢复完成的会话后可以继续；
运行中、切换中和恢复失败时禁止错投到其他会话；键盘、焦点和 live region 行为完整。T1507 不重新实现
Extension 的持久化历史投影或 Session 续接语义。

**测试**：新会话首次提交；同会话第二次提交；New chat；恢复后续接；Session 快速切换；
运行中禁用/取消路径；窄侧栏与键盘流程。

### T1508：统一生产 Token 估算与预算口径

**目标**：为历史、外部上下文和 Tool 消息提供确定性、宿主无关且对 CJK 不严重低估的估算。

**产物**：Core-owned 启发式计数器及注入点；所有上下文预算使用同一口径；序列化和计数受硬上限；
不把 vendor tokenizer 引入 Core。

**测试**：ASCII、CJK、空消息、Tool JSON、超长输入、确定性、预算边界和注入替身。

### T1509：贯通 Token Usage 的持久化与展示

**目标**：消费 Provider 已产生的 Usage 事件，并以有界、可恢复的方式展示实际用量。

**产物**：Core 事件、Protocol DTO、持久化投影和 Webview 展示；缺失或部分 Usage 有明确降级；
不得把价格、账单或估算值伪装成 Provider 实际值。

**测试**：有/无 Usage；多步累计；恢复；重复事件；取消后的迟到 Usage；数值上限和无效输入。

### T1510：处理上下文溢出与响应截断

**目标**：让上下文溢出和 `length` 截断成为可区分、可操作且有界的结果。

**产物**：稳定的 Provider-neutral 溢出分类；最多一次受控恢复；截断不伪装为正常完成；明确 UI 提示；
失败、取消、截断和溢出保持不同；不依赖第三方错误文案做控制流。

**测试**：首次恢复成功；再次溢出；普通 invalid request；截断文本；截断 Tool；取消优先；
恢复预算不足；无迟到重试或副作用。

### T1511：保留错误因果并审计 Provider 事件

**目标**：让 Core 审批准备、Tool 执行和 Provider 标准化失败可以安全诊断，而不泄漏秘密或依赖
第三方原始文案控制流程。

**产物**：稳定错误分类与内部 cause 链；结构化日志保留安全类别和拥有者；审计当前静默忽略的 SDK
事件并为 `tool-error`、`tool-approval-request` 等给出明确处理或有证据的拒绝；Webview 继续只接收
安全、可操作、无敏感值的错误投影。

**测试**：审批准备异常；Tool 执行异常；Provider tool error；未知 SDK 事件；敏感第三方错误；
取消优先；日志、持久化和 Webview 不泄密；原有稳定错误回归。

## 4. 阶段门禁

- T1501–T1511 全部完成并通过各自 PR 合入 `main`。
- 受控生产重试、覆盖率防回退和三个 OS 的基础 CI 证据先于多轮实现存在。
- 连续两轮集成测试证明第二轮包含必要历史，新会话不包含旧历史。
- 已完成、失败、取消和中断回合的续接语义与权威文档一致。
- 旧版单轮会话保持可恢复；任何持久化不兼容变化都有版本或只读降级方案。
- 审批、Run、取消和 Tool Result 不跨回合误复用。
- 历史、Usage、外部上下文和溢出恢复均受确定性资源上限。
- 错误保持安全可诊断，取消不被包装为普通失败，敏感第三方内容不进入用户投影或持久化。
- 单元、组件、Extension 集成、构建和人工恢复/续接路径全部通过。
